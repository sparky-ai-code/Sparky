# Sparky 1.1.2 Announcement

Sparky 1.1.2 is a major reliability release focused on making the agent more dependable when working on real projects.

This release also introduces persistent Memory, improves provider and model handling, strengthens conversation continuity, and gives the desktop experience clearer feedback while work is in progress.

## Persistent Memory is here

Sparky can now remember useful information across conversations and projects.

- Create, search, edit, and delete memories from Settings.
- Store memories globally or within a specific project.
- Reuse important preferences, conventions, and project context in future sessions.
- Memory storage works across supported platforms and includes migration and recovery handling.
- Memory failures are reported clearly instead of taking down the surrounding session.

## More reliable tool execution

Tool calls are now handled more carefully, especially during multi-step coding tasks.

- Improved reliability for file edits on Windows and CRLF-formatted files.
- Better handling of stale file content, ambiguous matches, malformed arguments, and incomplete tool calls.
- More useful error messages that tell the agent how to recover.
- Safer sequential edits that avoid applying changes from stale file snapshots.
- Better protection against accidental ambiguous replacements.
- Improved handling of large or truncated tool-call payloads.
- Clearer tool lifecycle states in the activity timeline, including Running, Completed, Failed, Stopped, and Declined.
- More accurate file-change diff statistics after tools finish.

## Stronger conversations and session continuity

Sparky is better at maintaining context throughout a long task and when returning to an existing session.

- Conversation history is persisted and reloaded more reliably.
- Follow-up turns continue the same session instead of silently starting over.
- Context compaction and context-window recovery are more robust.
- Incomplete provider streams are no longer treated as successful completed turns.
- Agent completion now requires a valid user-facing summary.
- Removed premature limits that could stop longer coding tasks before they were complete.
- Runtime session files no longer modify the user’s Git index as a side effect of loading a session.

## Better provider and model support

Provider handling has been strengthened across Sparky, Codex, and authenticated model sessions.

- More reliable provider event processing and turn lifecycle handling.
- Improved recovery from transient network and connection failures.
- Better retry behavior for interrupted provider requests.
- Improved ChatGPT OAuth model discovery.
- Account-aware context-window handling for Codex OAuth models.
- More accurate model context-window metadata and persistence.
- Better support for model reasoning capabilities and reasoning-effort options.
- Cleaner model picker behavior with fewer duplicate or confusing provider entries.
- Improved handling of provider session restarts and runtime bindings.

## A clearer desktop experience

The desktop application now communicates agent activity more clearly while work is happening.

- Running tools show an active loading state instead of appearing idle.
- Completed and failed operations are easier to distinguish.
- File changes retain their observed additions and deletions in the timeline.
- Memory settings provide clearer loading, retry, save, and deletion errors.
- Model selection is more consistent across provider types.
- Updated documentation, styling, and product presentation throughout the website.

## Release details

- Windows x64 installer rebuilt with version metadata **1.1.2**.
- Installer product name: **Sparky**.
- Existing update and compatibility routes remain unchanged.

Sparky 1.1.2 is about making the agent easier to trust: it remembers what matters, preserves context, reports what it is doing, and recovers more effectively when something goes wrong.
